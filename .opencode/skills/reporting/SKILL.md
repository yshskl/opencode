# Reporting Skill - 结果汇总规范

## 目的

定义任务完成后生成汇总报告的标准格式，确保报告内容完整、结构清晰。

## 适用范围

task-coordinator 主智能体汇总各子智能体执行结果时使用本规范。

## 报告结构

### 总览报告（返回给用户）

```markdown
# 任务完成报告

## 任务概述

[一句话总结完成的工作]

## 执行详情

### 任务1: [任务名称]

- 执行智能体: [子智能体名称]
- 执行状态: ✅ 成功 / ⚠️ 部分成功 / ❌ 失败
- 执行时间: [耗时]
- 产出的文件: [文件列表]

### 任务2: [任务名称]

- 执行智能体: [子智能体名称]
- 执行状态: ✅ 成功 / ⚠️ 部分成功 / ❌ 失败
- 执行时间: [耗时]
- 产出的文件: [文件列表]

## 质量检查结果

| 检查项   | 状态                | 说明   |
| -------- | ------------------- | ------ |
| 代码质量 | ✅ 通过 / ❌ 未通过 | [说明] |
| 测试覆盖 | ✅ 通过 / ❌ 未通过 | [说明] |
| 安全审查 | ✅ 通过 / ⚠️ 警告   | [说明] |

## 产出文件总览

| 文件                      | 类型       | 说明       |
| ------------------------- | ---------- | ---------- |
| context/requirements.json | JSON       | 需求文档   |
| context/schema_ddl.sql    | SQL        | 数据库脚本 |
| backend/src/...           | TypeScript | 后端代码   |
| frontend/src/...          | Vue        | 前端代码   |

## 下一步建议

1. [建议1]
2. [建议2]
3. [建议3]

## 注意事项

- [如有需要提醒的事项]
```

## 报告生成流程

```
执行任务
    │
    ▼
┌────────────────────────────────────┐
│         报告生成流程                 │
├────────────────────────────────────┤
│ 1. 收集各任务的执行结果              │
│ 2. 检查质量门禁结果                 │
│ 3. 汇总产出文件列表                 │
│ 4. 生成总览报告                    │
│ 5. 生成详细执行记录                 │
└────────────────────────────────────┘
    │
    ▼
报告文件
```

## 状态标记说明

### 执行状态

| 状态     | 标记 | 说明             |
| -------- | ---- | ---------------- |
| 成功     | ✅   | 任务正常完成     |
| 部分成功 | ⚠️   | 任务完成但有警告 |
| 失败     | ❌   | 任务执行失败     |
| 跳过     | ⏭️   | 因依赖失败而跳过 |
| 运行中   | 🔄   | 任务正在执行     |

### 质量检查状态

| 状态   | 标记 | 说明               |
| ------ | ---- | ------------------ |
| 通过   | ✅   | 检查项通过         |
| 警告   | ⚠️   | 检查项通过但有建议 |
| 未通过 | ❌   | 检查项未通过       |
| 不适用 | -    | 检查项不适用       |

---

## 字段说明

### 总览报告字段

| 字段         | 必填 | 说明                 |
| ------------ | ---- | -------------------- |
| 任务概述     | 是   | 一句话总结完成的工作 |
| 执行详情     | 是   | 每个任务的执行情况   |
| 质量检查结果 | 是   | 各阶段的质量检查结果 |
| 产出文件总览 | 是   | 产出的主要文件列表   |
| 下一步建议   | 否   | 可选的后续操作建议   |
| 注意事项     | 否   | 需要提醒的事项       |

### 执行详情字段

| 字段             | 必填 | 说明           |
| ---------------- | ---- | -------------- |
| task_id          | 是   | 任务唯一标识   |
| name             | 是   | 任务名称       |
| agent            | 是   | 执行的子智能体 |
| status           | 是   | 执行状态       |
| start_time       | 是   | 开始时间       |
| end_time         | 是   | 结束时间       |
| duration_seconds | 是   | 耗时（秒）     |
| output           | 是   | 产出文件列表   |
| quality_check    | 是   | 质量检查结果   |
| errors           | 是   | 错误列表       |
| warnings         | 是   | 警告列表       |

## 错误和警告处理

### 错误格式

```json
{
  "code": "ERROR_CODE",
  "message": "错误描述",
  "location": "文件路径:行号",
  "suggestion": "修复建议"
}
```

### 警告格式

```json
{
  "code": "WARNING_CODE",
  "message": "警告描述",
  "severity": "low|medium|high",
  "suggestion": "优化建议"
}
```

## 质量门禁结果汇总

### 汇总格式

```json
{
  "quality_gates": [
    {
      "gate_name": "代码编译",
      "status": "passed",
      "details": "无编译错误"
    },
    {
      "gate_name": "测试覆盖率",
      "status": "failed",
      "details": "覆盖率75%，低于80%要求",
      "suggestion": "补充更多测试用例"
    },
    {
      "gate_name": "安全审查",
      "status": "passed",
      "details": "无严重漏洞"
    }
  ],
  "overall_status": "partial",
  "passed_count": 2,
  "failed_count": 1,
  "warning_count": 0
}
```

### 总体状态计算

| 状态    | 条件                         |
| ------- | ---------------------------- |
| passed  | 所有检查项通过               |
| partial | 至少一项失败，但无阻塞性失败 |
| failed  | 有阻塞性失败，需要修复       |

## 下一步建议生成规则

### 根据执行结果生成

| 执行结果 | 建议                                    |
| -------- | --------------------------------------- |
| 全部成功 | 可以进行部署 / 可以进行下一阶段开发     |
| 部分成功 | 建议先修复失败的任务 / 可以在修复后继续 |
| 全部失败 | 建议重新分析需求 / 建议检查环境配置     |

### 根据质量门禁生成

| 检查结果   | 建议                     |
| ---------- | ------------------------ |
| 覆盖率不足 | 建议补充测试用例后再部署 |
| 有安全警告 | 建议修复安全警告后再部署 |
| 性能不达标 | 建议优化后再部署         |

## 示例报告

### 示例1: 成功报告

```markdown
# 任务完成报告

## 任务概述

用户管理系统开发完成，包含用户CRUD功能、角色管理和基本安全控制。

## 执行详情

### 任务1: 需求分析

- 执行智能体: requirement-analyzer
- 执行状态: ✅ 成功
- 执行时间: 2分钟
- 产出的文件: context/requirements.json

### 任务2: 数据库设计

- 执行智能体: database-designer
- 执行状态: ✅ 成功
- 执行时间: 3分钟
- 产出的文件: context/schema_ddl.sql

### 任务3: 后端API开发

- 执行智能体: backend-developer
- 执行状态: ✅ 成功
- 执行时间: 15分钟
- 产出的文件: backend/src/routes/user.ts, backend/src/models/user.ts

### 任务4: 前端界面开发

- 执行智能体: frontend-developer
- 执行状态: ✅ 成功
- 执行时间: 10分钟
- 产出的文件: frontend/src/views/UserManage.vue

### 任务5: 测试生成

- 执行智能体: integration-tester
- 执行状态: ✅ 成功
- 执行时间: 5分钟
- 产出的文件: tests/user.test.ts

## 质量检查结果

| 检查项   | 状态    | 说明       |
| -------- | ------- | ---------- |
| 代码质量 | ✅ 通过 | 无质量问题 |
| 测试覆盖 | ✅ 通过 | 覆盖率85%  |
| 安全审查 | ✅ 通过 | 无严重漏洞 |

## 产出文件总览

| 文件                              | 说明         |
| --------------------------------- | ------------ |
| context/requirements.json         | 需求文档     |
| context/schema_ddl.sql            | 数据库脚本   |
| backend/src/routes/user.ts        | 用户路由     |
| backend/src/models/user.ts        | 用户模型     |
| frontend/src/views/UserManage.vue | 用户管理界面 |
| tests/user.test.ts                | 测试用例     |

## 下一步建议

1. 可以进行部署到测试环境
2. 建议配置CI/CD流水线
3. 可以开始开发下一个功能模块

## 注意事项

- 用户登录使用JWT token，有效期7天
- 密码使用bcrypt加密存储
```
